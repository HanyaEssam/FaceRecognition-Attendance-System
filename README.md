# Face Recognition Attendance — FastAPI + React

Two separate apps that talk over HTTP:

```
backend/    FastAPI — all face recognition, liveness, mask detection, database logic
frontend/   React (Vite) — the dashboard UI, calls the backend's REST API
```

The Python CV pipeline (YuNet, SFace, liveness, mask heuristic) is **unchanged** from the
Streamlit version — it's the exact same `db.py` and `face_pipeline.py`, just wrapped in a
FastAPI HTTP layer instead of a Streamlit script.

---

## Backend setup

```powershell
cd backend
python -m venv venv
venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

**Download the three models** (same as before — see the model section below), placing them in `backend/models/`.

Run the API:
```powershell
uvicorn main:app --reload --port 8000
```

Check it's alive: open `http://localhost:8000/api/health` in a browser — should show `{"status":"ok","models_loaded":true}`. If `models_loaded` is `false`, the terminal will print exactly which model file is missing.

Interactive API docs (auto-generated by FastAPI) are at `http://localhost:8000/docs` — useful for testing endpoints directly without the frontend.

## Frontend setup

In a **second terminal**:
```powershell
cd frontend
npm install
npm run dev
```
Open `http://localhost:5173` in your browser. The frontend expects the backend running on `localhost:8000` (hardcoded in `frontend/src/api.js` — change `baseURL` there if you run the backend elsewhere).

**Important**: the webcam is now accessed through the **browser** (React's `WebcamCapture` component uses `navigator.mediaDevices.getUserMedia`), not directly by Python. Your browser will ask for camera permission the first time you visit the Check In/Out or Add Employee pages — allow it.

---

## Models (same three as before)

1. **YuNet + SFace** — run `python download_models.py` from `backend/` (script carried over from the Streamlit version) or download manually from the OpenCV Zoo.
2. **Liveness model** — clone `facenox/face-antispoof-onnx`, copy the **non-quantized** `models/best/98.20/best_model.onnx` to `backend/models/face_antispoof_v2.onnx`. Do NOT use the quantized version — it uses an op OpenCV's DNN can't load.

Place all three `.onnx` files in `backend/models/`.

## What's implemented

- **Dashboard** — total employees, attended/absent today, visitors this month, on-time/late %, most-attending employees & by work hours (bar charts via Recharts), attendance by department
- **Check In/Out** — live webcam capture, liveness check, face match, mask flag, auto-logs check-in/check-out
- **Employees** — search/filter, per-employee profile (National ID, Job Title, Gender, Religion, Marital Status, Birth Date, Address, Status — editable now, designed for future HR-system sync by Employee ID), delete with confirmation
- **Add Employee** — 3-photo capture enrollment via browser webcam
- **Visitors** — anyone detected who isn't a recognized employee is logged here instead of erroring out
- **Attendance Log** — date range filter, search/department/status filters, CSV/XLSX export, print
- **Camera toggle bar** — matches the reference layout (main gate in, Vip out, Vip in, Hr out, Hr in, out_camera, main gate out). **Still a UI placeholder** — this POC has one webcam, so these don't route to separate physical cameras yet.

## Known limitations (same as before, still worth stating to a manager)
- Liveness detection is single-frame RGB, not true depth — catches most casual spoof attempts, not a determined one with a great photo.
- Mask detection is a heuristic, not a trained classifier.
- SQLite is fine for this POC scale, not for production scale.
- Employee profile fields sync manually for now, not yet wired to a real HR system.
- Deleting an employee deletes their attendance history too — no undo.
